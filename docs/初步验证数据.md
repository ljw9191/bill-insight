本文件记录初赛提交所需的量化验证结果，全部由仓库内脚本对可复核素材实测生成，未做任何估算或补造。

复现命令：


## 一、 OCR 识别准确率

素材：`public/samples/wechat-ocr-demo.png`（微信支付账单详情，1528×1840）经浏览器同款预处理
（灰度 YIQ 权重 + 阈值 200 二值化，见 `src/lib/parser.ts` 的 `enhanceScreenshot`）后的增强图，
由 `scripts/gen_variants.py` 生成，保证测量对象与浏览器实际输入给 OCR 引擎的图一致。

| 指标 | 优化前（2026-11-13 上午） | 优化后（当前） |
|---|---|---|
| 字符错误率 CER | 2.2% | **1.1%** |
| 字符准确率 | 97.8% | **98.9%** |
| 字段级准确率 | 80%（4/5） | **100%（5/5）** |
| 金额识别 | 186.50 → 误识别 186.20 | **186.50 正确** |
| 单张识别耗时 | 389 ms | 485 ms |

|---|---|---|---|
| 日期 | 2026-11-08 | 2026-11-08 | 正确 |
| 收支方向 | 支出 | 支出 | 正确 |
| 金额 | 186.50 | 186.50 | 正确 |
| 商户 | 海底捞火锅 | 海底捞火锅 | 正确 |
| 分类 | 餐饮 | 餐饮（置信度 0.84） | 正确 |

### OCR 优化过程（问题定位 → 消融实验 → 修复）

优化前金额字段错误（186.50→186.20）。为定位根因，做了 16 组消融实验
（`scripts/ocr-experiment.mjs`，模型 fast/best × 放大 1x/1.5x × 二值化 190/200/210/无）：

| 方案 | CER | 金额正确 | 单张耗时 |
|---|---|---|---|
| fast（原）+ 原图 | 2.2% | 错 | 339 ms |
| fast（原）+ 二值化 | 4.4%–1.1%（随阈值跳变） | 不稳定 | ~300 ms |
| **best（现）+ 二值化 190/200/210** | **全部 1.1%** | **全部正确** | ~430 ms |

结论与修复：

1. 原 CSS `contrast(1.3)` 滤镜预处理会破坏金额笔画（数字 5→2），已移除，改为与测量脚本逐像素一致的纯灰度 + 阈值 200；
2. `chi_sim` fast 模型对预处理参数敏感，换成 `chi_sim` best 模型（12.5 MB）后在全部阈值组合下稳定 1.1%；
3. 新增商户清洗规则：去除 OCR 在汉字间插入的空格（"海底 捞 火 锜"→"海底捞火锅"），商户字段由错误转为正确；
4. 遗留已知误差：`¥` 仍被识别为"半"，但金额提取不依赖货币符号，不影响字段结果；后续按"金额区域裁剪 + 数字白名单"继续优化。

## 二、 内置分类规则命中与一致率

素材：与 `src/lib/demo.ts` 一致的 18 条标注账单（商户 + 备注），按真实分类入口 `classifyBill()` 计算。
本次 OCR 优化不涉及分类逻辑，两项指标与优化前一致。

| 指标 | 结果 |
|---|---|
| 样本数 | 18 |
| 规则命中率（置信度 ≥ 0.72） | 94.4%（17/18） |
| 分类一致率（与人工标注一致） | 94.4%（17/18） |

未命中样例：`公共交通 / 上月交通汇总` → 判为「其他支出」，置信度 0.3。
该样例没有套用内置的「交通」分类，而是**如实降到低置信度并交给用户核对**，说明低置信度暴露机制生效，不是静默给出错误结论。

## 三、 反馈反哺机制验证

素材：3 条不含内置关键词的构造商户（明确标注为构造用例，仅用于验证机制，不计入准确率统计）。

| 阶段 | 命中率 | 一致率 |
|---|---|---|
| 修正前（仅内置规则） | 66.7%（2/3） | 66.7% |
| 用户修正 3 条、生成个人规则后 | 100%（3/3） | 100% |

结论：一次修正即可沉淀为个人规则，并在后续同类账单上稳定命中，符合赛题要求的「用户修正反馈」闭环。

## 四、 容器部署实测（2026-11-19）

环境：Windows 11 家庭版 + WSL2（WSL 3.0.5，内核 6.18）+ Docker Engine 29.9.3。

| 验证项 | 命令 | 结果 |
|---|---|---|
| 镜像构建 | `docker compose -p billinsight build` | 成功，镜像 293 MB（多阶段：构建阶段与运行阶段分离） |
| 容器启动 | `docker compose -p billinsight up -d` | 约 16 秒进入 `healthy` |
| 健康检查 | `curl http://127.0.0.1:8080/health` | 返回 `ok` |
| 首页与静态资源 | `curl -I /`、`/tessdata/chi_sim.traineddata` | 均 200 |
| 卷持久化 | 容器内写 `/app/data/persist-check.txt` 后 `docker restart` | 重启后文件仍可读回 |
| 令牌鉴权（容器内） | 设置 `VAULT_TOKEN=demo-token` | 无令牌 401 / 正确令牌 200 / 错误令牌 401 |
| 端口映射 | `docker ps` | `0.0.0.0:8080->8080/tcp` |

补充说明：国内网络直连 Docker Hub 不可用，基础镜像经国内镜像源拉取后本地打标签；真实部署时可用 `docker compose build` 前配置镜像加速器。
